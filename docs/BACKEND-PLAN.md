## 为什么现在补后端

界面已经把「服务器管理」这件事的形状画出来了，但里面有一批块写着 `待接入` / `还没接后端`，还有一批是**界面上看不出来、一点就会踩**的坑。这一轮先把后者干掉——因为那些是「能不能真的开起服来」的问题，不是功能多少的问题。

盘点时发现的四类问题：

| 类型 | 例子 |
| --- | --- |
| **写了没接** | `ResolveJava()` 实现完整，`Start()` 完全没用它，直接 `java -jar` |
| **写了没路由** | `Manager.Update()` 存在，但没有任何 HTTP 路由能调它 —— 实例改名/改内存都做不到 |
| **承诺没兑现** | 向导文案写着「崩之前最后 200 行日志会单独存档」，后端没有 |
| **真 bug** | `AutoRestart` 是 `3 秒 → 重开` 无上限，配置错误时会变成无限重启循环 |

### 启动链路

| 项 | 接口 / 位置 | 说明 |
| --- | --- | --- |
| 启动前体检 | `GET /api/instances/{id}/preflight` | 六项检查：服务端文件 / EULA / Java 版本 / 端口占用 / `server.properties` 端口一致性 / 内存上限。每项带 `code` / `level` / `title` / `detail` / `fix` |
| EULA 一键写入 | `POST /api/instances/{id}/eula` | 原文件存在就只替换 `eula=` 那一行，保留服务端自己写的注释；代理端（Velocity / BungeeCord）跳过这项检查 |
| 一键修复 | `POST /api/instances/{id}/fix` `{code}` | 支持 `accept_eula` / `sync_port` / `rescan_java`。前端只认 code，怎么修是后端的事 |
| Java 自动选型 | `Manager.Start` → `ResolveJava(JavaForVersion(mc))` | 优先级：调用方指定 > 实例配置 > 按版本自动挑。以前只有 Java 8 的机器上跑 1.21 会直接抛 `UnsupportedClassVersionError` |
| 启动失败带报告 | `POST .../start` 返回 **409 + preflight 报告** | 只回一句错误字符串的话，界面就只剩「启动失败」四个字 |
| 自动重启护栏 | `Manager.supervise` | 退避 5s / 20s / 60s，累计 3 次后停下并给一句人话；跑够 180 秒才算「稳定」，之前才清零计数 |
| 崩溃现场存档 | `data/logs/<id>-crash-<ts>.log` | 最后 200 行 + 退出信息 + 时间，兑现向导里的承诺 |
| 日志落盘 | `data/logs/<id>.log` | 单文件 8 MB 滚动、保留 5 份。**刻意不写实例目录的 `logs/`**——那里是 Paper 自己的地盘，两边同时写会互相穿插 |
| 控制台命令回显 | `[ServerBox] > list` | 不回显的话用户敲完会怀疑自己到底按没按回车 |

### 配置读写

| 项 | 接口 | 说明 |
| --- | --- | --- |
| 实例编辑 | `PUT /api/instances/{id}` | 整体覆盖式（前端手里本来就有全量对象）。`CreatedAt` / `Dir` 由 Manager 兜住不可改；端口范围、内存下限都会校验 |
| server.properties 读 | `GET /api/instances/{id}/properties` | 23 个已知字段（带 `kind` / `label` / `hint` / `options`，直接驱动界面控件）；文件里我们不认得的键**附在末尾只读展示**，不藏起来 |
| server.properties 写 | `PUT /api/instances/{id}/properties` | 只替换传进来的键，其余行与注释原样保留；`backup.go` 之外唯一会写实例目录的地方 |

校验规则：int 必须能解析、bool 只能 true/false、enum 必须落在选项里、任何值不许带换行。宁可在这挡住，也别写进去让服务端整份配置回退成默认值（它还不给任何提示）。

### 数据目录绝对化

`NewManager` 里 `filepath.Abs(baseDir)`。默认值是 `./data`，直接进配置的话，之后以别的 cwd 启动（注册成服务、计划任务）路径全对不上。

## 全局设置 + 访问鉴权：已落地

代码在 `internal/settings/`（配置存储 + 密码/令牌）与 `internal/api/auth.go`、`internal/api/settings.go`。

### 设计决策（都是有理由的，别随手改）

| 决策 | 理由 |
| --- | --- |
| **默认不挡人**：`requireAuth=false` + `trustLoopback=true` | 装完就能用。一上来就逼设密码，多数人只会随便打一个然后忘掉，比不设更糟 |
| **只在「暴露到非回环 + 没开保护」时才告警** | 只监听本机却弹红色警告，是在制造噪音。`isExposed()` 判的是绑定地址：`:23333` 这种没写主机的形式 = 所有网卡 = 暴露 |
| **会话用 Cookie，不用自定义请求头** | 日志流走的是 EventSource，它**设不了请求头**。用 Cookie 才能让 SSE 一起受鉴权保护；用请求头就得给 SSE 单独开洞，等于整条链路放开 |
| **拒绝「开了保护但没密码也没令牌」** | 那种状态会把自己锁在外面。API 直接回 400 并说明缺什么，而不是存下去让人下次连不上 |
| **改密码 / 清密码都必须先给旧密码** | 清密码 = 关掉保护，是安全敏感操作。只有能证明自己是主人的人才能关 |
| **改完密码把所有会话踢下线** | 改密码的动机通常就是「怀疑别人知道了」 |
| **令牌只存 sha256，明文只在生成那一刻返回一次** | 列表里只剩前 12 位明文用于辨认。拿不回来是唯一诚实的做法 |
| **回环判定不看 `X-Forwarded-For`** | 那个头客户端可以随便伪造，拿它决定「免登录」等于把鉴权送人 |
| **会话存内存，重启要重新登录** | 家用面板可以接受，换来「改密码 = 所有人下线」这种干脆语义 |
| **监听地址只存不热切** | 热切换会丢连接。配置里存一份、`runtime.bindingAddr` 报实际绑的那份，不一致就提示「重启后生效」 |

### 首次启动的现状（实测）
`runtime.exposed = true` —— 守护进程绑的是 `:23333`（所有网卡），而保护没开。
所以设置页一进去就是红色告警，说清「同一个 Wi-Fi 下任何设备都能启停你的服务器、删你的存档」。

### 实测记录
- 鉴权开关：关时全放行；开后 `/api/*` 全 401（`{"error":"需要登录","needAuth":true}`），`/api/health` 保持开放
- 回环豁免：本机 `curl localhost` 免登录；关掉豁免后立刻 401
- 登录 → Cookie → 带 Cookie 访问 200；错密码 401；登出后 Cookie 失效 401
- 令牌：Bearer 头 200、`?token=` 200（给 EventSource 用）、伪造令牌 401
- 令牌列表响应里**不含 hash 字段**，且记录了最后使用时间
- 改密码：不给旧密码 401「当前密码不对」；给对了 200，且**旧会话立刻 401**（revokeAll 生效）
- 边界：开保护但无密码/令牌 → 400 且说明原因

## 服务端 jar 一键下载：已落地（Paper + 原版）

代码在 `internal/fetch/`，接口在 `internal/api/fetch.go`。全部经真 API + 真下载验证。

### 摸了真实 API 之后才知道的事（别再凭记忆改）

| 事实 | 说明 |
| --- | --- |
| `api.papermc.io/v2` → **410** | 已下线 |
| `api.papermc.io/v3` → **403** | **不是这个域名**。按「v2 升 v3 就是改版本号」去猜会全 403 |
| **`fill.papermc.io/v3`** ← 真正在用的 | 下载域名 `fill-data.papermc.io`，支持 Range；这台机器可直连 |
| Paper 下载项键名是 **`server:default`** | v2 时代叫 `application`，老代码不能照抄 |
| Paper v3 的 `/versions/{v}/builds` 返回**数组**不是对象 | 顶层直接是 `[{id,time,channel,commits,downloads}]` |
| Paper 版本表是**倒序**的，且混着 rc/pre | 我们只保留正式版，并自己排一遍序 |
| 原版元数据里有 **`javaVersion.majorVersion`** | 权威值。Paper 的 API 不给，就去查同版本的原版元数据补上 |
| **Paper 各版本的构建通道差别很大** | 1.21.4 → 100 个全 STABLE；**26.3 → 62 个里 0 个 STABLE**（14 BETA + 48 ALPHA）；1.21.11 → 63 STABLE + 17 BETA + 12 ALPHA。→ 默认必须选「最新的**稳定**构建」，不能取列表第一个 |
| **BMCLAPI 只镜像原版** | 它的 papermc 路径是 **404**。所以镜像按类型过滤，界面上不给 Paper 挂这个选项 |

### 实现要点

- **下载器**（`fetch.Manager`）：任务表 + 进度上报 + **断点续传** + **SHA 校验** + 取消。
  并发上限 2（再多只是在一条家用宽带上互抢）。进度每 200ms 上报一次，不是每 64KB。
- **续传的隐蔽坑**：`server.jar.part` 还在就从它的大小发 `Range` 续传，但**必须先把已有分片喂进 hash**，
  否则校验值永远是错的 —— 表现为「文件下完了却校验不通过」，看起来像源站的锅。已实测通过。
- **落盘用 `rename`**：避免出现「半个 jar 被当成完整的」。Windows 上要先删再 rename。
- **下载完的收尾**（`Options.OnDone`）：写 `server.properties`（只写文件里还没有的键，已存在的一个字不动）、
  往实例控制台写一行日志。不做这步的话，用户在向导里选的端口根本不生效 —— 服务端会用默认 25565。
- **进度用轮询不用 SSE**：几十秒的任务，轮询断了重连天然没问题；SSE 还要处理重连和事件补偿。
- 元数据带 **10 分钟 TTL 缓存，且按 base 分桶** —— 不分桶的话换镜像会读到上一次的缓存。

### 前端

- `components/ServerPicker.tsx`：版本 / 构建选择器，**向导和配置页共用同一个**（两边各写一套的话，
  「哪个构建是最新的」这种逻辑迟早不一致）。默认选「最新的稳定构建」；一个都没有时明确警告并给替代版本建议。
- `components/DownloadBar.tsx`：按 taskId 轮询的进度条，显示阶段 / 百分比 / 速率 / 校验结果。
- 向导：第 2 步换成真版本列表（55 个 Paper 正式版 / 103 个原版 release）；第 3 步从「手动放 jar」改成「自动下载」；
  第 5 步变成「创建 → 写 eula → 下载」三段式，下载失败可单独重试或先跳过进世界。
- 配置页新增「服务端文件」组：换版本 / 重下一份。**默认版本取实例当前的 MC 版本**，不是最新的。

## UI 重做的两轮（记下来，免得以后不知道现在这样是为什么）

### 第五轮 · 修「乱、看不清」
用户原话：「文字和信息的排版让人觉得杂乱不舒服，不知道为啥……对比度啊什么的感觉乱乱的，有些甚至看不清」。
拆成三条可量化的原因，全部修掉：

1. **对比度** —— 辅助色 `ink-3` 对底色只有 **3.97:1**（低于 AA 的 4.5），却承担了满屏 11px 小字。
   提到 `#8b978a` → 6.13 / 5.41 / 4.93（base / panel / panel-2）全部达标。
   ⚠ 分割线 `--color-line` 只有 1.5–1.9:1 是**刻意**的，分隔线不该抢眼。
2. **字阶** —— 一屏混用 6 种字号。定成封闭的 7 档（22/16/14/13.5/12/11.5/11），全局收敛。
   **等宽字体只留给机器数据**（路径/端口/时间/版本/key），中文散文挂 mono 会 fallback 成另一套字体。
3. **描边层级** —— 原先面板、区块标题、卡片内行、每个 chip 各有一圈黑边。现在强描边只允许出现在
   「容器」和「可点击控件」两级，中间一律 1px 弱线，**chip 彻底去边框**。
   另外卡片内行分隔线必须比卡片底色**更亮** —— 用近黑色会读成「裂缝」而不是「分隔」。

顺带：备份页那三个「用不了的灰控件」拿掉了（摆着不能用的控件比直接说「还没做」更让人困惑）。

### 第六、七轮 · 版式与动效
- 用户否掉了「一页摊全部字段」，拍板 **左分组导航 + 右侧只显示一组 + 滚到底切组 + 搜索**（对比稿见 `docs/designs/D-config-compare.html`）
- 动效定在**顺滑档**：140 / 220 / 300ms + ease-out，**不用弹跳曲线**。留了 `body.no-anim` 总开关
- **原生控件去割裂**：不用 `<input type="number">`（它的 spinner 是浏览器画的白色小箭头），
  数值一律走 `StepInput` 的 `[-] 值 [+]`；滚动条全局统一
- 参考过 PCL2（GitHub `Hex-Dragon/PCL2`）：它的设置页就是左分类 152px + 右内容，分类只有 4 个粗粒度，
  自带 `MySearchBox`，列表项默认带缩放入场动画。**只借鉴思路，代码一行没抄**（LICENCE 约束见 MEMORY.md）

## 设计上守住的两条

1. **不静默失败。** 没接的功能就写「还没接后端」并说清卡在哪（插件市场那块就是这么写的）。装了但不起作用，比明确说「没有」更伤信任。
2. **错误必须可操作。** preflight 每条 issue 都带 `fix`；崩溃重启停下时直接告诉用户「十有八九是配置问题，改好手动启动」，而不是丢一段栈。
