## 一、一句话看清四家的物种

| 项目 | 形态 | 技术栈 | 生态位 |
|---|---|---|---|
| **MCSL2** | 桌面单机开服器 | Python + PyQt5/QFluentWidgets | **和我们同一生态位**，最该逐条对照 |
| **MCSManager** | Web 面板（面板 + 多守护节点） | Node/TypeScript | 服务商级，功能上限参照，形态不必学 |
| **OPanel** | **跑在服务端里的插件** | Java/Kotlin + Gradle | 唯一拥有「服内视角」，玩家/世界做到最深 |
| **PCL2** | **客户端游戏启动器** | C# / .NET（闭源） | **物种不同**：管的是"玩"，我们管"开"。只当 UX 标杆 |

两条关键分野，决定「抄什么、不抄什么」：

1. **OPanel 能做的事，有一半建立在我们物理上做不到的位置上**（它就在 JVM 里，能直接摸玩家对象、区块、背包 NBT）。所以对 OPanel 要有取舍地抄，不能照单全收。
2. **PCL2 不是我们的竞品，是"同一批用户手里的另一件工具"**。它是启动器、我们是面板；它做得好的地方（版本/加载器选择、错误可读性、零配置开箱即用）是**要学的 UX**，它有的客户端功能**不是我们的缺口**——这条边界必须在文档里划清楚，否则会自己给自己造一堆假待办。

## 二、PCL2 专项：物种不同 —— 能学什么、什么不算缺口

**先划边界。** PCL2（Plain Craft Launcher 2，作者龙腾猫跃，2019 年至今持续更新，C#/.NET，开源，
国内玩家首选启动器之一）是**客户端游戏启动器**：它管的是「怎么把游戏跑起来、把模组装对」，
我们管的是「怎么把服务端稳稳地开起来、出事能查、数据不丢」。**两者不构成替代关系**，
所以它有的客户端功能（版本管理、光影、皮肤、正版登录、内存优化）**一律不算我们的缺口**——
写进这份文档是为了划清边界，不是给自己造待办。

它值得学的是**同一批用户已经被教育过的交互习惯**。下面每条都给出「学什么」与「我们现在的状态」：

| # | PCL2 的做法 | 我们对应在哪 | 结论 |
|---|---|---|---|
| 1 | **Java 自动诊疗**：自动扫描本机全部 Java（分架构/版本）→ 按 MC 版本算出**所需版本区间** → 自动挑最合适的 → 找不到就调 Mojang Java 列表自动下载；也允许手动指定路径；**每个实例各自记住自己的 Java** | `probeJava`(`-XshowSettings:properties`) + `JavaForVersion` + `fetch/jdk.go` 下载源 | ⚠ **有一条值得复核**：我们是「按大版本映射」，它是「按区间匹配 + 实例各自记住」。见下方「可直接照抄的一条」 |
| 2 | **错误提示可读性**：崩溃时自动定位问题模组并给中文解决方案，而不是甩一段栈 | `crash.go` + `CrashPanel`（现象/原因/怎么办） | 同思路，我们已具备，继续保持 |
| 3 | **下载引擎**：多下载源自动切换 + 断点续传 + 单文件多线程 | 分片下载 + 多基址回退（Modrinth 官方→镜像；Forge→BMCLAPI）+ 续传（`.part` 先喂 hash，`TestDownloadCreatesMissingDestDir`） | 同方向；我们的差异是**校验三件套**（对 size → `is_zipfile` → 换源），比单纯重试更硬 |
| 4 | **零配置开箱即用**：绿色免安装、解压即用、不写注册表、体积小 | 单 exe 双击即用（`bin/serverbox.exe`） | **是我们的核心定位，与它同向**，不是差距 |
| 5 | **内置帮助库/教程**降低入门门槛 | 「preflight 每条带 fix」「错误必须可操作」（产品原则②） | 同一种善意的不同实现 |
| 6 | **功能入口可关闭/可隐藏**（不想要的功能藏起来） | 反其道：我们**不给没落地的东西开入口**（产品原则⑦） | 取舍不同，不必照搬 |

### 不算我们缺口的东西（明确列出，防止以后被误当待办）

> ⚠ **2026-10-11 边界修订**：项目定位改为**全能型**（服务端 + 客户端一体），
> 下面这条「客户端专属不算缺口」**已作废** —— 客户端功能列表见
> [`CLIENT-SIDE-ROADMAP.md`](./CLIENT-SIDE-ROADMAP.md)。「装饰型个性化」那条仍然有效。

- **客户端专属**：客户端版本/实例管理、OptiFine/光影包、皮肤与披风、正版/离线/第三方登录、多账号、
  内存优化（G1GC 参数建议）、联机房间 —— 全部属于「玩游戏」，**不进我们的待办清单**。
- **装饰型个性化**：自定义背景音乐/背景图、XAML 自定义主页、主题商店 —— 与项目规范「克制、零渐变、

### ⚠ 可直接照抄的一条（唯一一条具体行动项）

PCL2 的 Java 选择是**「版本区间匹配 + 每个实例各自记住」**；我们 `JavaForVersion` 目前是**按大版本号映射**。

1. **同一实例换过 Java 之后，是否真的记住了自己的选择**（而不是每次回落到「按版本算出来的默认」）。
2. **是否需要"区间"语义**（如「1.20.5+ 需要 21」这类边界），而不是只按主版本号查表。

> ⚠ **证据强度**：PCL2 为闭源软件，以上事实来自其官网（`pcl2.aoe.top`）、公开更新日志与第三方使用指南
> （2026-10-06 检索），**未做源码级核实**；涉及内部实现的说法（如 `ModJava.vb` / `GetJavaRequirement`）

## 四、P0 —— 最痛的两块（用户会直接开口要）

### P0-1 计划任务系统　**← 已完成 ✅（2026-10-05）**

曾是最大的一块空白（**三家全有，只有我们没有**）。现已落地：`internal/daemon/tasks.go` +
`internal/api/tasks.go` + `web/src/components/TasksPanel.tsx`，触发四型 + 动作七种，
与自动备份**共用同一个 30 秒调度循环**（没有另起 goroutine）。

下面保留当初的竞品设计取证，供后续加动作类型时对照：

- **MCSManager**（`frontend/src/widgets/instance/Schedule.vue`）：
  - 时间三型：`INTERVAL`（间隔秒）/ `CYCLE`（cron）/ `SPECIFY`（指定日期时刻）
  - 动作六种：`delay` / `command` / `stop` / `start` / `restart` / `kill`
  - 带执行次数统计（`count`）、列表可编辑可删
- **MCSL2**（`MCSL2Lib/Pages/schedulerPage.py`）：
  - 触发两类：`cron` + **控制台输出正则匹配**（`re.search(pattern, output)` 命中即触发）
  - 动作四种：`command` / `save` / `stop` / `start`
  - 内置 Cron 生成器（简易模式：每分钟/每 5 分钟/…/每月 + 自定义间隔；专业模式：五段式表达式）
  - 配置存 `Servers/{name}/scheduler_config.json`，支持导入导出
- **OPanel**（`core/.../task/`）：`ScheduledTask` + `TaskCommandParser` + `TaskBuiltinOperation` + **变量注入**（任务里可用变量）

当初预判的坑（实现时均已处理，留作回归清单）：
- 动作要**串行队列 + 超时**，`stop` 之后必须等进程真退出再 `start`，否则撞端口（复用 preflight 的端口占用检查做二次确认）
- `output` 触发要防抖：一行日志同时命中多条规则、或规则里 `.*` 匹配每一行，都要限频
- 任务的 `lastRun` / `nextRun` 与备份策略一样，**必须后端算好返回**，前端不重算

### P0-2 玩家管理

**只有 OPanel 有**（`PlayersController` / `WhitelistController` / `BannedIpsController`）。但它是开服之后第一个会被问的功能——现在用户只能自己爬到控制台敲 `whitelist add xxx`。

**关键判断：我们不需要做服务端插件，也能做到 80%。**

OPanel 是站在 JVM 内部直接调 API；我们换个路线，靠**原生文件 + 控制台命令 + 日志解析**三件套：

| 数据 | 来源 | 说明 |
|---|---|---|
| 白名单 | `whitelist.json` | `[{"uuid":"...","name":"..."}]` |
| OP | `ops.json` | `[{"uuid","name","level","bypassesPlayerLimit"}]`，`level` 1–4 |
| 玩家封禁 | `banned-players.json` | 含 `reason` / `expires` / `source` |
| IP 封禁 | `banned-ips.json` | 同上结构 |
| 在线玩家 | 控制台 `/list` + 日志 | 解析 `xxx joined the game` / `left the game` |
| 实时动作 | 控制台命令 | `kick` / `ban` / `pardon` / `op` / `deop` / `whitelist add|remove` |

⚠ 坑（值得先写测试）：
1. **离线模式 UUID 不是真 UUID**。离线服里玩家 UUID = `md5("OfflinePlayer:" + name)` 的带连字符形式。手工拼错会让白名单加了人却进不去。
2. 这些 json 文件**服务端运行时也会写**，我们改的时候要做「读-改-写 + 落盘后请服务端 reload」；直接覆盖可能被服务端内存里的状态盖回去。更稳的是**改文件之后同时发一条 `whitelist reload`**（Paper/vanilla 都支持）。
3. 中文 / 特殊字符玩家名要按 UTF-8 处理，`ops.json` 不带 BOM。

**建议范围**：在线玩家列表（含 K/D 不做）→ 白名单增删 → OP 增删（含 level）→ 封禁/解封（玩家 + IP）→ 一键踢人。这就覆盖了 OPanel 那一页的全部实际用途，而**不需要任何服务端插件**。

### P0-3 游戏规则编辑器

OPanel 的 `GamerulesController`。我们没有。

两条路线：

| 路线 | 做法 | 成本 | 风险 |
|---|---|---|---|
| **A. 命令枚举（推荐）** | 服务端启动后发 `/gamerule`（无参）→ 解析返回的全部规则与当前值 → 按已知类型表渲染成开关/数字 | 低 | 需要服务端在跑；解析要跟着本地化文案走 |
| B. 读 `level.dat`（NBT） | 直接解析世界存档里的 NBT | 高 | 要写 NBT 读解析器；且服务端跑着时改了会被回写覆盖 |

走 A。类型表（bool / int）在后端写成唯一真相源，和 `properties.go` 的 23 条 spec 同一个套路——**那张表已经证明了这条路走得通**（有 `properties_test.go` 断言每项都有 Group/Label/合法 Kind）。

⚠ `/gamerule` 输出的规则名与显示名混在一起，且不同版本规则集会变（新版本会加/改规则）。**不要硬编码全集**，按「解析到什么就显示什么、认得类型就给控件、不认得的按文本框兜底」处理——这就是「不静默失败」原则在这里的落法。

## 五、P1 —— 让面板从「能用」到「好用」

### P1-1 配置文件编辑器升级

MCSL2 的 `configEditorPage.py` 是**纯文本编辑器**（不是结构化表单），但它的三项设计值得我们学：

1. **多标签页**：同时开 `server.properties` + `paper-global.yml` + `spigot.yml`，标签带 `*` 未保存标记
2. **语法高亮**：json / yml / toml / ini / properties / log 六种
3. **保存策略**：`Ctrl+S` + 60 秒空闲自动保存 + **关闭标签时自动保存**

它的取舍很聪明：**不解析、不重组 → 注释与未知键天然 100% 保留**。这正是我们现在 `WriteTextFile` 的行为。

**我们的缺口**：
- 现在文本编辑只覆盖「文件」页里随便点一个文件，没有语法高亮、没有多标签、没有未保存提示
- 真正高频的编辑对象是 `config/*.yml`（插件配置）、`spigot.yml`、`paper-global.yml`——纯文本改 yml 一旦缩进错一个空格，插件直接静默失效

**建议做法**（纯前端 + 少量后端，复用已有 `ReadTextFile` / `WriteTextFile`）：
1. 编辑器加 yml/json/toml/ini/properties 五档高亮（别引 Monaco——几十 KB 的东西要引一个 2MB 的编辑器，和单 exe 定位冲突；用轻量高亮即可）
2. **保存前对 json / yml 做一次语法校验**，错了就指明行号并**拒绝保存**——这一条比高亮更值钱（高亮只是好看，校验能防事故）
3. ⚠ 现在的文本读取**拒绝 >1MB 与含 NUL 的文件**（`ErrTooLarge` / `ErrNotText`）。升级时要区分：`config/*.yml` 通常很小没问题，但**历史日志**要能打开 → 给日志单独一条「只看尾部 N 行」的读取路径
4. ⚠ 行尾：仓库里 `web/**` 多数是 CRLF，往编辑器里塞内容时别把 CRLF 洗成 LF（`server.properties` 被我们和 Paper 两边写，一旦统一成 LF 会在 git 里制造噪音）

### P1-2 存档管理独立化

OPanel 的 `SavesController`：上传 / 下载 / 删除 / **启用**（多世界切换）。

我们现在备份页能做「整实例备份」和「只存档备份」，还原也支持——但缺少**存档粒度的搬运**：
- 把 `world/` 单独打包**下载**到本地
- 从别处**上传**一个存档压缩包并替换
- **多世界**：同时存在 `world` / `world_nether` / `world_the_end` / 自定义世界，能切换启用哪个

实现上是 `FileManager` + 备份能力的自然延伸，后端 `ExtractZipAt` / `SaveUploadTo` 已经在 `filebrowser.go` 里躺着。

⚠ 关键约束（我们在备份页已经踩过）：**实例运行中不许动存档**（JVM 正在按自己的节奏写 region 文件）。`App.tsx` 里 `canWipeFiles` 已经建立了正确的判据（`!running && status !== 'starting'`），直接复用。
⚠ 另一个已修的坑别退化：`RestoreBackup` 是「只清这份备份确实含有的顶层条目」，不是「清空整个实例目录」。存档搬运要用同一套判据。

### P1-3 监控历史与图表

OPanel 有完整 `monitor/` 模块（CPU / 磁盘 / 网络采样 + 历史聚合 + 图表）；MCSManager 有 `InstanceChart`。

我们的现状：`GET /api/instances/{id}/metrics` 只给**瞬时值**，前端在内存里攒 60 个点画曲线，**刷新页面历史就没了**，后端一个字节都没存。

**建议**：后端落盘采样。
- 采样 10 秒一次，写 `data/metrics/<id>.jsonl`（追加式，天然不怕中断）
- 保留 24 小时原始 + 7 天降采样（1 分钟均值），滚动清理
- 新增 `GET /api/instances/{id}/metrics/history?range=1h|24h|7d`
- 图表指标：CPU、内存占用/上限、**在线玩家数**、磁盘占用（`syscall` 或目录扫描）、TPS（从控制台 `/tps` 解析）

⚠ 顺带解决一个已有隐患：「玩家数」这个指标依赖 P0-2 的日志解析，两块可以一起设计。
⚠ 别把采样做成每实例一个 goroutine —— 备份调度器已经确立了「**单个定时器按分钟粒度扫**」的规矩（`BACKEND-PLAN.md` 里明确写了），同一台家用机上开十个实例就起十个 goroutine 是纯浪费。

### P1-4 审计 / 操作日志

MCSManager 有 `AuditLog.vue` + `OperationLogCard.vue`。我们**完全没有**。

这件事的严重性来自我们自己做的一个决定：**我们支持给面板设密码 + 发多枚令牌**（`/api/settings/tokens`，只存 sha256，带最后使用时间）。也就是说——**多人可以用同一个面板**。而现在已经有了这些不可逆操作：

- 删除实例（可带 `wipe` 清空目录）
- 还原备份（会覆盖当前存档）
- 强制结束（可能损坏存档）
- 删除文件 / 删除备份
- 改 `server.properties` 与实例配置

**出了事没人能回答「谁干的」。**

**建议**：后端 append-only 操作日志，字段 `时间 / 来源IP / 凭据（密码会话 or 令牌名）/ 动作 / 目标 / 结果`。
- 写 `data/audit.jsonl`，单文件 8MB 滚动、保留 5 份——**`logfile.go` 已经实现了这套滚动逻辑，直接复用**
- 只记「写」操作，不记读（不然一秒三条没人看）
- 设置页给查看入口 + 按动作/时间过滤
- ⚠ **绝不记密码与令牌明文**（令牌只存 sha256 这条规矩要延续到日志里）
- ⚠ 鉴权默认是关的（`requireAuth=false` + 回环豁免），所以日志里要如实体现「本机免登录操作」，不要伪造成某个用户

## 六、P2 —— 深水区与「看情况」

### P2-1 开放 API（只读对外）

OPanel 有 5 个 `OpenXxxController`（`OpenInfo` / `OpenLogs` / `OpenMonitor` / `OpenPlayers` / `OpenPlugins`），定位是**给服务器官网展示实时状态**。

我们已经有令牌机制，但它的语义是「完整管理权限」——把它给一个官网页面用，等于把启停和删除权限一起交出去了。

**建议**：独立的 `/api/open/*` 只读子集（在线状态 / 玩家数 / 版本 / 运行时长 / 最近一次备份），设置页给开关（**默认关**，开了要有和现在「非回环 + 无保护」同款的红色告警）。

⚠ 别用令牌去复用管理接口——权限粒度完全不同，混在一起迟早出事。

### P2-2 MCP Server（AI Agent 接入）

OPanel 单独开了 `opanel-mcp` 仓库，支持 Claude Code / OpenClaw 管服务器。

**这条对我们性价比异常高**：我们已经有 65 条 REST 路由、语义清晰、有鉴权。做 MCP 就是**纯包装**，不用动后端。工具集建议：列实例 / 查状态 / 启停 / 发指令 / 读日志（尾部 N 行）/ 触发备份 / 搜模组 / 装模组。

⚠ 危险动作（`kill`、删除实例、还原备份）在 MCP 里必须是**两段式**（先返回确认信息，再执行），不能让 AI 一句话就把存档清了。

### P2-3 通知 / 离线告警

三家**都没有集中做**，但对「家里闲置电脑开服」这个场景是刚需：人不在电脑前，服务器崩了、备份失败了、磁盘满了，全靠回头去看。

我们已经有崩溃判定（`stoppedGracefully()`）和备份调度器，**挂勾子的位置都是现成的**。建议先做 Webhook（企业微信机器人 / 钉钉 / Server酱），事件：启动完成 / 崩溃 / 备份成功失败 / 磁盘阈值。成本很低。

### P2-4 服务端类型补齐

- **NeoForge**：`fetch.Sources()` 里现在标 `false`。但 NeoForge 与 Forge 同构（`maven.neoforged.net` + installer + `--installServer`），而我们 `forge.go` 已经写完了两段式安装与产物实况探测（spec=1 → `forge-<tag>-shim.jar`，spec=0 → `forge-<tag>.jar`）。**这是低成本高价值的一条。**
- **基岩版**（MCSL2 已支持）：`bedrock_server.exe`，不走 java。进程模型不同，`Track` / 停服信号要单独适配——**别再探**这条，等有真实需求再动。
- **BungeeCord**：同 MCSManager 也有（作为代理端）。我们已经在 preflight 里对代理端做了「跳过 EULA」的区分，说明代理端的概念已经进来了，补齐成本中等。

### P2-5 多语言 i18n

三家都有（OPanel 甚至有简体/繁体/粤语/英/日/法/德/韩 7 种）。我们全中文硬编码。**除非要公开发布，否则优先级最低**——先把功能补完。

## 七、暂时不做的（**分两档，别当成铁律**）

> **用户 2026-10-05 拍板**：Docker 确定不做；其余几项**暂缓、保留可能性** —— 不是永久排除。

### 7.1 确定不做

> **用户 2026-10-05 补充拍板**：Steam 页也不做。

| 功能 | 出处 | 理由 |
|---|---|---|
| Docker 容器运行 | MCSManager | 家庭电脑上装 Docker 的成本 > 收益。我们的定位就是「单 exe 双击即用」，引入容器等于把最大优势扔掉 |
| Steam 游戏服页（Palworld / Squad / Terraria 等） | MCSManager | 定位就是 MC。多一类游戏 = 多一套进程模型 + 下载源 + 配置体系，分散掉「把 MC 这一件事做透」的精力。**用户 2026-10-05 明确：不做** |

### 5.2 暂缓（保留，等真实需求再动）

| 功能 | 出处 | 现在的判断 / 重启条件 |
|---|---|---|
| 分布式多节点 | MCSManager | 一台家用机用不上。**重启条件**：真出现「管多台机器」的需求 |
| 多租户 / 商业托管权限 | MCSManager | 面向 IDC 售卖。我们「密码 + 令牌 + 审计日志」这一档够用。**重启条件**：真要给别人开服收钱 |
| 拖拽卡片式仪表盘 | MCSManager（LayoutCard 16 种卡片） | 复杂度高，且与已拍板的「克制、别滥用卡片」规范有张力。**重启条件**：只有「可自定义首页」这个需求真的被反复提 |
| 背包编辑 / 物品 NBT 编辑 | OPanel | 不是不想做，是**位置不对**：OPanel 站在 JVM 内部直接操作玩家对象，我们只能读 `level.dat`。**重启条件**：我们改成插件形态，或接受只读离线存档的降级版 |
| 内置实时地图查看器 | OPanel | 区块追踪 + 瓦片渲染 + 压缩 + 前端地图库，工作量远超收益。**重启条件**：地图成为核心卖点（那就得先解决「拿不到实时区块」这个前提） |
| 自动更新 + 在线公告 | MCSL2 | 注意一个反向证据：MCSL2 **最新版把在线公告和更新检查都移除了**（ChangeLog「优化」段落明写）。这类联网行为反而被嫌弃。我们本来也没做，保持 |
| 插件 / 扩展系统 | 三家都有 | Go 单 exe 加载外部代码有安全与分发成本。**更划算的替代**：开放 API + Webhook + 在计划任务里支持「执行本地脚本」——三样加起来覆盖 90% 的扩展需求，且不引入运行时风险。**重启条件**：替代方案被证明不够用 |

## 八、我们已经领先的（写下来，防止以后改退化）

| 能力 | 对照事实 |
|---|---|
| **停服三层判定** | MCSManager 靠 `ignoreEventTaskOnce` 标记 + 次数上限，**根本不看退出码**；MCSL2 把崩溃判定**整段注释掉了**。我们的 `stoppedGracefully()` 有规格表测试（`shutdown_test.go`） |
| **启动前体检每条带 fix** | 三家都没有等价物。preflight 六项检查 + `POST /fix` 一键修复 |
| **崩溃原因判读** | MCSL2 有 `serverErrorHandler.py` 规则匹配，我们已有 `crash.go` + `CrashPanel`（现象/原因/怎么办） |
| **模组依赖自动安装** | Modrinth `requiredDeps` → `DepDialog` 两段式（先列候选让人确认，不静默装最新版）。MCSManager 的 ModManager、OPanel 的插件管理都只是「启用/禁用」 |
| **中文名搜索** | 自建 MC百科离线快照（`zhname.go` + `mcmod_zh.json` 166KB）+ `/api/mods/translate`。**MCSManager 完全没有中文检索层**；OPanel 靠插件形态自带 |
| **自动备份的语义精度** | `since`（启用时刻）与 `lastRun`（真跑过）**分开两个字段**，刚打开不会撒谎说「上次备份：现在」；范围可选；保留策略手动/自动统一计 |
| **「不静默失败」的落地密度** | 错误边界三层、骨架屏三态、全局断连横幅、`?nosse=1` 可见提示——这套东西是靠一个个真实事故堆出来的，竞品没有 |
| **服务端视角的整合包市场** | 搜 Modrinth 整合包（默认只列 `server_side != unsupported`）→ 预览「这个包开服要下多少、要不要 EULA、什么加载器」→ 一键开成**新**实例。MCSL2 的整合包偏客户端；MCSManager 的市场是通用资源管理器，**没有"开服代价预览"这一步**。规格 `MODPACK.md` §9 |
| **一次性取件码缓存（`packToken`）** | 预览时下过的包，安装时**不再重下**；作业表 + 全局下载台账（右下气泡）可见。竞品的下载是"一部到位"型，没有这种"预览—确认—复用"的两段式 |
| **自研 Markdown 渲染，无 `dangerouslySetInnerHTML`** | 源站描述先 `plainText()` 清洗、HTML 块先降级再解析、标签白名单。竞品的描述区多用富文本/`innerHTML`，我们走的是**不可注入**路线 |
| **整合包详情页 / 模组详情页共用同一外壳** | `ProjectShell.tsx`（版心居中 + 页内分页 + 左右两栏吸顶）；纯函数抽到 `projectMeta.ts`。版面一致性能靠复用强制保证，不靠人自觉 |
