# 客户端功能清单（全能型方向）

> **为什么有这份文档**：`COMPETITOR-GAP.md` 当年把「客户端专属功能」明确划在边界外
>（版本管理 / 光影 / 皮肤 / 正版登录 / 内存优化 / 联机房间……「全部属于玩游戏，不进待办清单」）。
> 项目定位改为**全能型**（服务端 + 客户端一体的 MC 工具）之后，**这条边界改了**：
> 客户端从「不是缺口」变成「就是要做的下一大片」。本文件就是那片功能的清单。
>
> 盘点日期：2026-10-11。参照物：PCL2 / HMCL / PrismLauncher / MCSL2（客户端侧）。
> ⚠ 与 `COMPETITOR-GAP.md` 的旧边界冲突时，**以本文件为准**；旧文件里那条「不算缺口」需同步修订。

## 前置约束（决定怎么做，比做什么更重要）

- **单 exe 定位**：客户端资源（`assets/` 可达数 GB、`libraries/`、`client.jar`）**不能打进 exe**，
  必须落在数据目录、按需下载。
- **版权/合规**：`client.jar` 与 `assets` 只能从 Mojang 官方源下载，**不得随包分发**；
  加载器安装器同理（走官方/镜像下载，不入库）。项目是 GPL-3.0，注意与上游许可证兼容。
- **复用已有地基**（这是本项目的优势，别重写）：
  - 作业框架 `internal/jobs` + `/api/jobs` → 客户端下载/安装/解压一律走它，**气泡进度自动就有**
  - 下载层 `internal/fetch`（分片 + 校验 + 换源，已被服务端侧验证过）
  - Java 管理：`JavaForVersion` 已是**区间语义**（`<1.17`→8、`<1.20.5`→17、否则 21）；
    `POST /api/java/download` 已有
  - 模组市场 / 整合包解析（`.mrpack` / Modrinth）服务端侧已有，客户端可复用同一份解析器
  - 崩溃判定：服务端侧已有规则，客户端崩溃日志可共用一套「谁炸的」归因
- **UI 规范不变**：零圆角零渐变、图标禁 emoji、克制；主题商店／背景音乐／装饰型个性化**仍不做**。

## P0 —— 起一个「能玩」的客户端（最小闭环）

没有这些，客户端功能无从谈起。

| # | 功能 | 说明 | 复用 |
|---|---|---|---|
| 1 | **原版版本安装** | 拉 Mojang version manifest → `version.json` → `client.jar` + `libraries/` + `assets/`（按 index 增量下） | `internal/fetch` + `internal/jobs` |
| 2 | **加载器安装** | Forge / NeoForge / Fabric / Quilt（LiteLoader 可选）；走各自 installer 或 maven 直取 | 服务端侧已有 Forge/NeoForge/Fabric 安装逻辑，**客户端侧是同构问题** |
| 3 | **客户端实例模型** | 每个版本一个隔离目录：`mods/ config/ saves/ resourcepacks/ shaders/ options.txt`；支持复制/重命名/删除 | 与现有服务端实例共用「实例目录」概念，但**独立模型** |
| 4 | **启动参数生成** | 主类 + classpath + **natives 解压** + JVM 参数（内存/GC）+ 游戏参数（窗口/分辨率/全屏） | 服务端侧 `buildArgs` 是路径驱动，客户端参数结构不同，需单写 |
| 5 | **登录** | 微软正版（OAuth 设备码流）+ 离线登录；令牌本地加密存 | 全新（服务端侧无需登录） |
| 6 | **Java 运行时** | 自动探测 + 按实例记住选择（见下方「待核」）+ 一键下载 | `JavaForVersion` + `/api/java/download` 已有 |

**待核（来自 COMPETITOR-GAP 的「唯一具体行动项」）**：
`JavaForVersion` 已是区间语义 ✅；但**「同一实例换过 Java 之后是否真的记住自己的选择」尚未核实** ——
实例对象有 `javaPath` 字段，要看 preflight / 启动路径是否优先用它、而不是每次回落到按版本算的默认。
做成客户端时这条必须明确（用户原话是「每个实例各自记住」）。

## P1 —— 装模组不折腾（客户端体验的核心）

| # | 功能 | 说明 | 复用 |
|---|---|---|---|
| 7 | **模组管理** | 拖入 jar 安装、启用/禁用（`.disabled`）、缺依赖提示、冲突检测 | 模组市场数据 + 服务端侧依赖检查逻辑 |
| 8 | **资源包 / 光影** | 拖入、启用/禁用；光影提示需 Iris/OptiFine | 全新（轻量） |
| 9 | **整合包导入导出（客户端侧）** | `.mrpack` / CurseForge zip / Modrinth → 装成客户端实例 | **服务端侧导出已完成，客户端侧是同构的反向操作** |
| 10 | **存档管理** | 单存档上传/下载/删除、跨实例复制（与服务端侧「存档管理」同一份能力，做成共用） | 备份能力已是地基（zip + jobs） |
| 11 | **多账号** | 账号切换、皮肤/披风显示 | 与 #5 同源 |

> 与 `COMPETITOR-GAP.md` 里 P1「存档粒度搬运」重合：**一次做成服务端/客户端共用**，别做两套。

## 明确不做（沿用旧边界里仍成立的部分）

- 主题商店、自定义背景音乐/背景图、XAML 自定义主页 —— 与本项目「克制、零渐变、禁 emoji」规范直接冲突。
- 一切需要联网却对用户无直接价值的「运营型」行为（除非用户显式开启）。

---

## 建议的开工顺序

1. **先定实例模型**（#3）——客户端实例 vs 服务端实例是否共用模型，这个决定后面所有功能的形状；
2. **P0 的 #1+#2**（版本 + 加载器安装）——最硬的骨头，跑通即证明「全能型」可行；
3. 再补 #4/#5/#6（能启动、能登录）；
4. P1 里优先 **#9 整合包导入**（服务端侧已有，反向最省力）与 **#10 存档管理**（与服务端共用）。
