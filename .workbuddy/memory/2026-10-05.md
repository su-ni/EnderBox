**用户**：「还是抽搐？？？」——上一轮留的"阈值线+滞回"没解决。这轮不猜了，直接测。

**复现手段**（`F:/tmp/diag_stuck.mjs`）：CDP 驱真 Chrome，用 `Input.dispatchMouseEvent`
发**真实滚轮事件**（不是赋值 scrollTop，那样走不到浏览器的夹取逻辑），每帧采样

**抓到的决定性一帧**（未修复，短结果列表）：
```

t=7788  stuck=false  head=435  scrollTop=57   文档高=1708   ← scrollTop 被浏览器夹掉 181px
t=7820  stuck=true   head=595  scrollTop=337  文档高=1868
```

**根因**：`position: sticky` 的元素仍占文档流。面板收起 618→369，整份文档就矮 249px。

**修法（`useStableScrollRange`）**：塌陷掉多少，就在**滚动区末尾**补回多少，
让滚动区总高全程不变。用 ResizeObserver + 过渡期 rAF 逐帧量差值（不写死 249px，
塌陷量随断点/文案变）。配套 `STUCK_HYST` 32 → **120**：RO 的回调比盒子变化晚一帧
（实测塌陷中途最多差 56px），滞回盖过这个赤字才彻底断环。

## 15:35-16:00 · 翻 PCL2 源码，拿到中文搜索的完整答案

用户说「pcl是怎么做的？翻他源码」→ 通过 SSH over 443 浅克隆 `git@github.com:Hex-Dragon/PCL2.git`
（`GIT_SSH_COMMAND="ssh -F ~/.ssh/watchme.d/github-443.conf"`，9 秒完成，29MB）。

**答案在 `Plain Craft Launcher 2/Modules/Resource/ResourceSearcher.vb` 的 `#Region "中文搜索"`**：

1. 输入转小写 → `StrConv(VbStrConv.SimplifiedChinese)` **繁转简**；
2. `[\u4e00-\u9fbb]` 判汉字，且**只对 Mod / 数据包启用**（整合包名字本身可能已含中文）；
3. 到**内置表 `WikiEntry.All`** 里模糊配（`Search(entries, rawText, 100, 0.25)`，相似度阈值 0.25）：
   完全匹配优先 → 相似度最高 → 再 `MaxBy(Popularity)` 选**百科浏览量最高**的那个；
4. `ExtractWords()` 从该条目的 **slug** 和 **中文名括号里的英文**抠出纯英文词：
   丢长度 ≤1、丢数字（`Val(w)>0`）、丢非 ASCII、丢停用词
   （`the/of/mod/and/forge/fabric/for/quilt/neoforge`），再剔除"能由其他词拼成"的冗余词
   （`enderio` vs `ender io`）；
5. **用这串英文当替代搜索词**发给 CurseForge / Modrinth；Modrinth 侧还额外拿 top100 的 slug 直接请求工程；
6. 一个都匹配不上才抛 `MSG_NO_CHINESE_RESULT`。

### 几个必须记住的设计决策（都写进了代码注释）

1. **任务独立存 `data/tasks.json`，绝不挂在 `Instance` 上。**
   `PUT /api/instances/{id}` 是整体覆盖。备份策略兜底成空策略无害，但**任务列表兜底成空 =
   静默删光用户配好的定时任务** —— 前端只要有一处提交实例时没带 tasks 字段，配置就没了且无任何提示。
   → 独立 store + 四条独立路由（同 backup-policy 的既有规矩）。
2. **固定时刻类只看今天，错过的不补跑。** 晚上关机、第二天早上开面板时，「每天 23:00 备份」
   不该补一次；「每晚 04:00 重启」更不该在上午突然重启。间隔式相反 —— 它本来就该追赶。
3. **`nextAfter` 必须「严格大于」起点。** LastRun 记的就是刚跑过的那个时刻，允许等于会让
   30 秒一轮的调度器把同一条任务**每 30 秒跑一次**（自己咬尾巴）。有专门测试钉死。
4. ⚠ **午夜任务的 1 纳秒坑**：固定时刻的起点要抬到「今天 0 点**前一瞬**」而不是「0 点」——
   `nextAfter` 严格大于，拿 0 点当起点会把「今天 00:00」这个触发点本身排除掉，
   于是**每天 00:00 的任务永远不触发**。只在午夜现形。
5. **LastRun 不论成败都记**（与备份相反）。备份失败不记是为了当天可重试；任务失败若也不记，
   30 秒后就会再撞一次 —— 永远起不来的实例配「每小时重启」会退化成每 30 秒拉一次 JVM。
   失败原因进 `LastError`，界面顶部单独列出。
6. **动作失败即中止**后面的动作。尤其「重启失败后还继续执行强制结束」很危险。
7. **异步派发**：`RunDueTasks` 同步（给测试），生产走 `dispatchDueTasks` 用 goroutine 发 ——
   动作里有 `delay`（最长 1 小时）或大世界备份（几分钟），同步跑会把整个调度循环卡住。
8. `StartBackupScheduler` → **`StartScheduler`**：备份和任务共用**一个** 30 秒 tick，
   不各起一个 goroutine。
9. `tasks.json` 坏了（JSON 语法错）**不 fatal**，挪成 `.bad-<时间戳>` 再用空库启动 ——
   附属数据不该把整个守护进程打死（用户连界面都进不去、更没法自己修）。
10. CRON 自研精简版：五段式，支持 `*` `*/n` `a` `a-b` `a-b/n` 和逗号列表。
    **日与周同时限定时取「与」**（标准 cron 取「或」），更好解释。扫满一年放弃（2 月 30 日那种），
    靠「小时不对就整点跳」把扫描量压到秒级。

**⚠ 血的教训：我把 MC百科 抓封了。**
为了赶时间把并发从 2 提到 8（瞬时几十 req/s 的机器人行为）→ 先是一批 **HTTP 429**，
接着整机 IP 被防火墙封禁。封禁页原文：

**最关键的一条：封禁页返回的是 HTTP 200**（不是 403），只看状态码会把它当成正常页面，
结果是「每页都解析出 0 条」然后静默产出一份残缺的表 —— 那比直接失败危险得多。

## 16:40-17:00 · 「已装界面有时候没有模组图标」——查出是真 bug

**诊断手法（有效，记下来）**：不要盯着代码猜，**逐个打图标接口 + 直接列 zip 条目**：
```
遍历 /api/instances/{id}/plugins → 对每条打 /plugins/{file}/icon
→ 看「hasIcon=true 但接口 404」的组合（那才是 bug；hasIcon=false 本来就该是占位图标）
→ 再直接 zipfile.namelist() 看那个 jar 里到底有没有声明的图标文件
```
实测表：Connector 标着 `hasIcon=true iconPath=logo.png`，接口 **404**；其余三个都 200。

**根因**：`Connector-1.0.0-beta.49+1.20.1.jar` 是 Forge 的**外套 jar** —— 真模组和它的
`logo.png` 都在 `META-INF/jarjar/Connector-…-mod.jar`（**内层**）里，外层根目录只有
`fabric-mixin.jar` 和 `mappings.tsrg`。
`readModMetaNested` 会**钻进内层**读元数据（所以 `iconPath` 通过校验、列表标了 hasIcon），
**但 `ModIconFile` 只翻外层 jar** → 找不到 → 404 → 前端 `onError` 换成占位图标。
**两头用了两套解析**，于是出现「说有图标、给了 404」这种最费解的组合。

**顺手排除的假线索**：文件名里有 `+`，怀疑是 URL 转义 ——
实测「原样 / `%2B` / `quote_plus`」三种编码**全都 404**，不是转义问题。别急着改前端。

**修法**：`ModIconFile(jarPath, iconPath, nestedSource)` —— 把元数据的来源（`meta.Source`，
形如 `META-INF/jarjar/x.jar!META-INF/mods.toml`）传进去；`!` 前是内层 jar 的路径，
就把内层 jar 读出来（上限 64MB）在内存里当 zip 再找一遍；内层找不到再回外层兜一次。
`PluginIcon` 现在传 `meta.Source`。

**测试**：`TestModIconFromNestedJar`（造一个只有 `META-INF/jarjar/inner.jar` 的外套包，
断言图标取得出来）+ `TestModIconFromOuterJarStillWorks`（别为了修内层把外层弄坏）。
**拆掉修复 → 报的错正是真机上那个 `jar 里没有 logo.png`；还原 → 绿**。
另外旧测试的 `ModIconFile` 调用点跟着改了签名。
