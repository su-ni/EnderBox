## 星图改成「旋涡星系」+ 右侧信息面板按设计稿重做

**用户原话**（10-09 23:53）：「当前项目的模组页面有那个星图，我要的是星系形的，但是现在这个…………
而且点击模组后展开的那个小页面也没有按当前设计来」
→ 用提问框确认了两处指代：① 形态要 **旋涡星系式**；②「小页面」＝**星图右侧 `.mcg-side` 信息面板**
（不是「已安装」列表的 ModDetail 弹窗，也不是市场整屏详情页）。

### 为什么上一版不像星系（两轮试错，别再走回去）
1. **力导向 + 球面投影**（`layoutForce` + `z=±sqrt(1-r²)`）→ 一团球状点云；中心点被归一化推到一侧；
   三条 `.mcg-rings` 同心椭圆**与点位无关**（纯装饰，看着像乱画）；339 条边全画 → 毛球感。
2. **θ 只由半径决定**（`arm*π + TWIST*ln(r/R_INNER)`）→ 同层点半径几乎相同 → 全挤在两条臂的**同一相位**上
   → 画出来是两条又粗又短的竖弧：实测 302 点只占画布宽 **26%**（x 跨度 277px / 画布 1060px）。
3. **角度按「全局序号进度」**→ 1 层只占全局进度 8%，弧长也只有 8% → 1 层那 24 个点挤在 19° 扇区糊成一坨。

### 最终实现（`web/src/components/McmodGraph.tsx`）
- `spiralLayout()` 取代 `layoutForce()`：中心固定 (0,0,0)；其余点按 `deep` 分层的**半径带**
  （`baseROf` 几何级数 + `halfBandOf` 带宽，**故意让相邻层交叠** → 盘连续）；角度用**层内进度 frac**
  `θ = arm*π + (d-1)*ARM_PHASE + frac*ARM_LEN` → 「每层一小段螺旋、层间接起来＝一条连续旋臂」，
  `arm = 全局序号 % 2` → 两条对称臂；`OFF_ARM=12%` 不挂臂撒在盘上当场星。
  常量：`R_INNER=0.15 / R_OUTER=1 / ARM_PHASE=1.9 / ARM_LEN=1.7 / OFF_ARM=0.12`。
- **z 改成薄盘**（不是球壳）：`|z| = 0.04 + 0.16*exp(-(r/0.42)²)` —— 中心鼓成核球、盘缘薄，符号取 id 哈希。
- ⚠⚠ **归一化改成「半径等比缩放」`dispScale = 1/maxR`，推翻了原来那条「过滤后必须用 min/max 包围盒映射」**：
  那条是**散点力导向图**的经验；星系圆对称，按半径缩放天然让中心留在画布正中，用包围盒反而把中心推离中心、把旋臂拉歪。
  ⚠ `dispScale` 必须进 effect 依赖 —— 骨架要用同一个缩放，否则切档位后骨架与行星分离。
- ⚠ **层→半径/带宽/角度的算法只能有一份出处**（`baseROf`/`halfBandOf`/`layerOfRadius`/`armThetaAt`）：
  布局和旋臂骨架都调它。上一版骨架另写了个公式 → 与行星的角度规则对不上，**那正是用户说的「乱画」**。
- ⚠ `hash01` **不要写 `% 10000`**：取模会压出可测偏心，而它要用来做「几成贴旋臂」的比例判断。改用完整 32 位。

### 视觉

## 3D 感修复（用户验收星图后提：「为什么不是像之前那样 3d 的」）

**诊断**：不是缺 3D，是四个参数把立体感洗掉了。逐项查代码 + 推投影公式后发现：

1. **⚠⚠⚠ yaw 旋转轴写反（真 bug）**：拖拽注释写明意图＝「绕竖直轴」，实现却是 `x1 = x0·cosY + z·sinY`
   （转 x-z 平面）＝**绕水平 y 轴「翻滚」**。**Y=0 时两公式等价**（所以改版初看没露馅）+ 16° 低俯角把
   「翻滚 vs 转盘」的差异也藏住了。修正：`x1 = x0·cosY − y0·sinY; y1 = x0·sinY + y0·cosY` 再俯仰。
   **旋臂骨架同链同步改**（两条链必须同源，否则行星与虚线分离）。
2. **初始俯仰 16°→35.5°**（`pitchRef` 0.62，三处：初值/数据复位/复位按钮）：16° 近乎俯视，自转投影≈2D 转圈。
3. **盘厚 +25%**：`bulk = 0.05 + 0.20·exp(−(r/0.45)²)`（配合俯角，厚度屏幕投影翻 ~2.7 倍）。
4. **深度雾写全**：原 CSS 只写 5 档、最暗 0.72；改为 12 档 0.45→1.0，**并按探针实测校准**
   （BUCKETS 输出：常态只用 nth-child 4~9 → 重点梯度沿此铺满 0.60→1.0）。
5. **配套**：`ZMIN/ZMAX ±2.2→±1.2`（新链 z2 幅值 ≤1.02）、`D 4.5→3.2`（透视补回）。

**验证**：BUCKETS 铺开 2~8 档 ✅；S1/S2 中心点击 trace 正常（lost 在 up 后 + click 合成）✅；
截图对比 `star3d-spin-a/b.png`（相隔 12s≈40°）＋ galaxy/panel/center；exe `403f419b…`。

**教训**：3D「转得不像 3D」先查：俯角 / 转轴 / 深度线索（明暗·透视·厚度）。轴的错误在 Y=0 与低俯角下隐形；

## 承接式切页（PPT 平滑式）落地 + 页签指示条滑行 + 探针两个陷阱

**方向**（用户拍板）：切页要「承上启下」的平滑 —— 外壳/页签不动，旧内容下沉淡出、新内容从上方接进；

## 跟随收官（两个竞态）＋ 整合包确认框 ＋ 石头铺满真机（10-10 傍晚）

**三项用户需求全部落码并验证**（下轮已提问框请用户真机确认）：

1. **跟随「只跟一下下」＝两个竞态，不是一个**（探针 `probe_follow.mjs` 重写，11/11；A/B 判别项 T2/T5）：
   - ①**重贴守卫**（T3 逮到）：用户把 scrollTop 挪走后、异步 scroll 事件到达前，若来一次内容增长，
     重贴底 effect 会先把位置抢回底部 → 事件只看得到 gap≈0、连 peel 机会都没有。修：位置明显更靠上
     且不在底部 → 重贴让路（但「内容变少被夹回最大值」必须照常重贴，否则 stickyTop 够不着＝跟随假死）。
   - ②**回波令牌**（T5 逮到）：我们写 scrollTop 后、回波到达前，用户完全可能先 peel —— 回波晚到时会走
     `gap<8 → stick()` 恢复分支，把刚关掉的跟随**静默复活**（症状「滚不动/被弹回底部」）。修：`echoPending`
     令牌，onScroll 最前认领（位置还停在上次落点即整体忽略）；位置没动过的写入不占令牌。
   - 判据教训：T5 的 `min gap` 天然必败（peel 后元素仍在底部、首采样≈0）→ 改用 max≥400＋回贴计数=0；
     T6 用跨一次增长的两次采样；**相位锁定 `waitFreshGrowth()`**（等新增长刚发生再操作，~20% 假红→0）。
   - 旧产物基线对照：T2 min=500 / T5 max=0（红）；新产物全绿。
2. **整合包「一键装最新版」**：头部安装 → 确认框（最新版号/MC/大小/发布时间＋新建世界），两出口

   `probe_packconfirm.mjs` 8/8（打真守护+真市场，fabulously-optimized 14.1.0）；顺手把后端 404
   「没有这个升级作业」文案中性化为「没有这个作业」。
