## 项目启动：Minecraft 开服器

用户想在另一台电脑上开 MC 服务器并便捷管理，最初设想「基于 PCL2 开源项目改造」。

### 调研结论（关键，别再走回头路）
- **PCL2 不能作为代码基调**。仓库根目录 `LICENCE` 不是开源协议，是《PCL 分发有限许可》+《存储库合理使用指南》。
  - 重度使用（基于仓库修改 / 参考大量内容重新实现实质功能）强制要求：名称必须以 `Plain Craft Launcher (PCL)` 开头、Windows 上界面主色相必须为蓝色、公开源码、关于页首位署名龙腾猫跃+赞助链接、不得有类 PCL 的赞助解锁功能。
  - 等于无法做自有品牌产品。
- 技术错配：PCL2 = VB.NET + WPF + .NET Framework 4.5，Windows-only，本质是**客户端启动器**；开服器核心（进程守护、控制台交互、崩拉起、备份、穿透）PCL 里没有。
- 正确姿势：只借鉴产品感觉（一键、中文、多镜像源、崩溃智能分析），代码自研。

### 竞品格局
- MCSManager：Apache-2.0，Node.js，Master+Daemon 分布式，Win/Linux，中文，10 分钟装完 —— 功能全但像运维后台，不够傻瓜。
- Crafty Controller：Python(Tornado)，单体，仅单机，GPL-3.0，简单。
- Pterodactyl：PHP+Go Wings+Docker，重，需 Linux 功底，占 1.5-2G 内存。
- MCSS / MC Server Manager：Windows 桌面向，闭源。

### 差异化切口
「最后一公里」：让不懂 Linux、没有公网 IP 的人 30 秒内开服且朋友能连进来。
内置 UPnP + 内网穿透、Modrinth/CurseForge 整合包一键拉取、崩溃自动诊断与回滚、手机远程管理。

### 关键坑位（写进 DESIGN.md 了，别重复踩）
1. Windows 杀子进程必须用 Job Object（KILL_ON_JOB_CLOSE），否则崩遗留进程占端口
2. 日志主通道要 tail `logs/latest.log` 而非 stdout —— Windows 中文环境下 Java stdout 是 GBK 会乱码
3. 停止先发 `stop` 等优雅退出，超时 60s 再 kill
4. 热备份前必须 `save-off` + `save-all flush`，否则拿到半个区块
5. 各服务端安装方式完全不同，不能抽象成一套

### 三个真实踩坑（下次直接避开）
1. **Go sync.Mutex 不可重入**：`Manager.Start` 持锁时调用 `logsFor`（内部同锁）→ 自死锁，HTTP 永久挂起。修法：先取 logs 再加锁。
2. **headless 截图被 SSE 卡死**：前端加 `?nosse=1` 开关（长连接不建立）。
3. **Edit 工具偶发「报告成功但未落盘」**：本轮出现 5 次（main.go 的 time import、App.tsx 的 NOSSE、副标题、metrics 路由注册、newProcess 的 players 初始化）。**每次 Edit 后必须 grep 回验**，这是硬规矩。
4. **nil map panic**：`Process.players` 字段声明了但构造函数初始化没写进去 → `p.players[name] = struct{}{}` 直接 panic 整个守护进程。
   修法：改成在 `track()` 里懒初始化，不依赖构造函数。

### 关键教训：Windows headless Chrome 窗口最小宽度约 504px
- `--window-size=430` 实际 CSS 视口是 **489**，截图按 430 裁剪 → 表现为「右边缘全被切掉」，**极易误判成 CSS 横向溢出**。
- `--force-device-scale-factor=1` 也救不了。
- 正确做法：模拟手机**用 520 宽截**（仍在 `max-width:900px` 断点内）。
- 精确测量用注入探针 + `--dump-dom | grep title` 读回 `VW / body.scrollWidth / 溢出元素`，别靠肉眼。
- 三档实测结果：5 个页面在 489 / 991 / 1422 视口下 `body.scrollWidth == clientWidth`，零横向溢出。
- 另一个坑：`--window-size=1440` 实际视口是 **1422**（少 18px）；每张截图必须用独立 `--user-data-dir`，否则会被转给已运行实例而空截。

### 自测抓到的一个真 bug（值得记）
E 第一次截出来是**空白的**。查法：`node --check` 抽出的 script 段 → 语法没问题，说明是运行时抛异常；
再 `--dump-dom` 看产物 → `e-body` 里 1477 字符的内容其实**在**，`#note` 却是空的 → 定位到 `show()` 没跑完。

根因是我自己写的：
```js
show((location.hash||'#e').slice(1).match(/^[abcde]$/) ? location.hash.slice(1) : 'e');
//    └─ 判定用了带默认值的   └─ 传进去却用原始 hash
```
首次加载 `location.hash` 是空串 → 判定走 `'#e'` 通过 → 但传进去的是 `''` → `show('')` 里
`getElementById('v-')` 返回 null → 抛 TypeError。**而它抛之前那句「先摘掉所有变体的 `on`」已经执行了**，
于是五个变体一起 `display:none`，页面看着像整个渲染失败。

教训两条：
1. **判定用的值和传进去的值必须是同一个**，别一个用带兜底的表达式、另一个用原始值。
2. **「先清除、再重建」的写法里，中间任何一步抛异常都会留下空状态** —— 这类代码要把「算出来」和「应用上去」分开，先算完再改 DOM。

### 六条设计决策（都有理由，别随手改）
1. **默认不挡人**：`requireAuth=false` + `trustLoopback=true`。一上来就逼设密码，多数人只会随便打一个然后忘掉。
2. **只在「暴露到非回环 + 没开保护」时才告警**。只监听本机却弹红警告是噪音。
   `isExposed()` 判绑定地址：`:23333` 这种没写主机的形式 = 所有网卡 = 暴露（实测 `exposed=true`，正确）。
3. **会话用 Cookie 不用自定义请求头** —— 日志流是 EventSource，**它设不了请求头**。
   用 Cookie 才能让 SSE 一起受保护；用请求头就得给 SSE 单独开洞，等于整条链路放开。
4. **拒绝「开了保护但没密码也没令牌」** —— 那会把自己锁在外面。API 回 400 并说明缺什么。
5. **改密码 / 清密码都必须先给旧密码**（清密码 = 关保护，是安全敏感操作）；改完把所有会话踢下线。
6. **回环判定不看 `X-Forwarded-For`** —— 那个头可以随便伪造，拿它决定免登录等于把鉴权送人。

### 踩到 / 注意到的
- **`Disable` 分支的旧密码校验顺序**：`setPassword` 里旧密码检查在所有分支之前，
  所以「清密码」也必须带 `old`。我第一版测试没带 → 401「当前密码不对」，看着像 bug，其实是行为正确。
- 前端 `req()` 加 `credentials:'same-origin'`，并新增 `sbx-need-auth` 全局事件：

- App 的登录闸门放在**渲染之前**（而非某个子组件里）：未验证时任何面板数据都不该被请求出去。
- 设置页分页加了 `?tab=` 可寻址（和 `?page=`/`?g=` 一套惯例），顺便解决了「截图停在指定分页」。

  侧栏 WorldList 一层）。为此抽出 `PageFrame.tsx` 把「滚动容器 + 边界」合成一个组件 ——
  main 的 className（含 anim-fade）必须一字不差，而且直接包一层会让页面主体缩进两级。
  文案先安抚再说明：「守护进程和正在运行的服务器都没受影响」放最前。
- **骨架屏**：`ui.tsx` 加 Skeleton / SkeletonList / SkeletonFields。
  **用透明度脉动而不是渐变扫光**（这套设计禁渐变）。
- **全局断连横幅**：`ConnectionBanner.tsx`，跨在侧栏与内容之上，每页可见。

### 顺手修掉的三个真 bug（都是截图/实测才暴露的）
1. **插件页/备份页在数据回来前先渲染「目录是空的」/「还没有备份」** ——
   备份页那句等于在用户最在意的地方撒谎。补 loading 标记（try/finally）。
2. **首屏空态谎报故障**：`online` 初值 false，空态直接渲染成「连不上守护进程」。
   改成三态：没问完（正在连接守护进程…+骨架）/ 在线 / 离线。
3. **刚打开就弹「已重新连上守护进程」**：判据写成「online 从 false 变 true」，
   而首次成功加载正好符合。改成「上一次是『问过且没连上』」。
   这个只有在截图里看到 toast 才发现。

### 新增两个截图开关（沿用 ?nosse / ?probe / ?drawer 的套路，写在 src/dev.ts）
- `?crash=1` 定向抛异常，验证错误边界
- `?slow=1200` / `?slow=8000:plugins` 接口延迟，验证骨架屏。
  带路径过滤是必需的：列表骨架得先有实例列表才看得到，全局延迟会一起拖住。

### 环境坑（重要）
- **`rm -rf <目录>` 会被批量删除保护拦截**（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`，
  本次 398 个文件 > 阈值 50），**且失败会让整条 && 链中断**（表现为「服务起不来」其实压根没执行）。
  验证环境不要复用同一个临时目录再删，改开新目录名。
- **断连横幅没法用「先把后端停掉再开页面」验证** —— 页面本身就是守护进程发的。
  办法是用 `npx vite preview`（只发前端、没有后端）打开，接口全 502，正好是真实形态。
- 前端全是 CRLF（core.autocrlf=false）。改文件要「读时 .replace('\r\n','\n') 归一、
  写时 newline='\r\n'」，否则整文件行尾会被改掉。
- Bash 的 heredoc 在本机会被重写成会产生 `Bad substitution`（`${...}` 被当 shell 变量）。
  写补丁脚本要先用 Write 落成 .py 文件再执行，别走 heredoc。
- 补丁脚本常因沙箱重跑而在第二遍断言失败（第一遍已成功落盘）——
  看到 AssertionError 先 grep 确认现状，别急着改脚本。

## 真服务端全流程联调（15:24–15:36）——撞出 3 个真 bug

用真 Paper 1.21.4 跑「建实例 → 下载 → 体检 → 签 EULA → 启动 → 看日志 → 发命令 → 停服」，
全程走真 API（`bin/serverbox.exe -dir=F:/sbx-realrun -addr=:23399` + curl）。

**顺利的部分**：下载 49MB @19MB/s、SHA256 逐位对上、`server.properties` 按实例端口生成、
EULA 一键修复、启动到就绪 **18.2s（首启含重映射）/ 11.6s（二启）**（承诺 30s，富余）、
`list`/`say` 命令往返正常、优雅停服 2s、强杀无孤儿（Job Object 扛住了）。

### Bug A：jarPath 为空 → java 收到空 `-jar`（已修）
- `process.go buildArgs` 用原始 `inst.JarPath`，而体检/下载用的是 `resolveJar()`（会兜底 server.jar）。
- 后果：**体检说「文件没问题 ✅」，一点启动就 `Unable to access jarfile` 秒崩** —— 自相矛盾，
  正好砸在「不静默失败」的立身之本上。前端向导默认填 jarPath 所以正常流程不爆，
  但 API 建实例 / 导入 / 旧配置全会爆。
- 修：`buildArgs` 改 `resolveJar(*inst)`；`Create` 里 jarPath 为空时兜底 `server.jar`。

### Bug B：强杀被误判成「崩溃」（已修）
- `Kill()` 写 `StatusStopped`，收尾 goroutine 只认 `StatusStopping` 是「人为停止」，
  于是又把它覆盖成 `StatusCrashed`。
- 后果：①用户主动停服却弹红色「已崩溃」；②**开了自动重启的会在用户刚杀完自己爬起来**；
  ③还写了一份假的「崩溃现场」档（实测确实写了）。
- 修：加 `intentional bool` 显式意图标记（不拿 status 当依据），Stop/Kill 都置位，
  goroutine 改判 `!p.intentional`。Kill 里先 `select` 探 `p.done` 是否已关，避免覆盖真实崩溃结论。

### Bug C：PID / 内存指标盯的是「转发器空壳」（已修，本次最隐蔽）
- 本机 PATH 里的 java 是 Oracle `javapath\java.exe`，它**会再 spawn 一个子进程**跑真 JVM
  （实测：壳 79292/10MB，真身 84352/1.29GB 才是 25565 的持有者，父进程是壳）。
- 后果：守护进程记 `cmd.Process.Pid` = 壳 → **面板内存显示 10MB、实际 1.3GB（差两个数量级）**。
  一个专门管服务器资源的工具给出这种数字，很伤。
- 修：`probeJava` 改用 `-XshowSettings:properties -version` 一次拿版本 + `java.home`，
  把路径**归一到 `<java.home>/bin/java`（真身）** → 没有壳、没有子进程，
  PID/内存/Job 竞态一并根治，顺带让设置页显示真实 JDK 路径。
  `probeJava` 是唯一收敛点（preflight 和启动都从这里取），改一处全局生效。
  配套：Default 标记改在探测前按「候选路径」判（归一化后就比不上了）；按归一化路径去重。
- **副作用踩坑**：`vendorOf` 原是全文子串扫描，加了 -XshowSettings 后
  `java.library.path` 里混进 `Microsoft.DesktopAppInstaller`，
  而 "microsoft" 排在 "oracle" 前面 → **Oracle 被误判成 Microsoft**。
  修：优先读权威属性 `java.vendor`（就一行，不会被带偏），读不到才退回全文扫。

### 待办（用户未拍板）
- **26.3 这个最新版**：20 个构建全是 BETA、且要 **Java 25**（本机只有 21）。
  前端已会警告「零稳定构建」，但「本机没这个 Java」要到启动体检才拦 ——
  用户会先下 54MB 才发现跑不起来。可考虑在选构建时就比对本机 Java。
- `PaperVersions()` 给每个版本都标 `stable:true`（只看名字里有没有 `-`，没看构建 channel），

### 环境坑（本次新增）
- **PowerShell 工具本会话不回显 stdout**（命令确实执行了，写文件正常）——
  要拿输出就让 PS 写文件再 Read。
- **bash 直接调 `powershell.exe` 被安全策略拦**（"Invoking PowerShell from Bash bypasses ..."）。
- `2>&1 > file` 会把顺序写反（stderr 跑终端、file 拿 stdout），要写成 `> file 2>&1`。
- 补丁脚本锚点若在插入后仍然存在（拿上一行当锚），**沙箱重跑会重复插入**
  （本次 `vendorPropRe` 被声明两遍 → `redeclared in this block`）。
  锚点要用「插入点前后各带一行」，或替换前先判 `if new in text`。
