# 设计稿「全屏式 + 去松」改造（用户：面偏松 / 要铺到健康条 / 中间不要左右缝）

用户原话（语音，有识别错误）：「整个面还是偏松 …… 尽量搞成全屏式的，让它完全覆盖下面的健康条，
中间的内容区域不要有左右缝隙」。逐条落地：

## 一、左右缝隙 → 0（`.content` 的 22px 内边距是元凶）

原来 `.content` / `.tabbar` / `.world-head` 都是 `padding: 16px 22px 0`，主区内容左右各让出 22px。
改成 `padding: 16px 0 0`（左右归零），实测 `leftGap=0 rightGap=0`。
**判据**：`_layout.py` 直接量 `.page.on .panel` 左边界 - `.content` 左边界。

## 二、健康条 60px → 48px，主区底部留白 78 → 50

`.hud { height: 48px }`，`.main { padding: 0 0 50px }`，`.side` 的 `padding-bottom` 同步 60→50（否则侧栏比主区早 10px 结束，露出断层）。

## 三、⚠⚠ 踩了两个坑（都值得记）

**坑 1：`flex:1` + `min-height:0` 会把内容压扁，不是"撑满"。**
想让 `.content` 纵向铺到健康条，写了 `.content{flex:1;min-height:0}` + `.grid-2{flex:1 1 auto;min-height:0}`。
结果 1440×900 下 **`.grid-2` 从 438px 被压成 151px**，里面的 panel 溢出到 y=1051（视口才 804）——
看上去像"面板被裁掉一半"。flex 子项默认 `flex-shrink:1`，父容器不够高时它会**缩**。
→ 正解 `flex: 1 0 auto`：**只长不缩**（空间富余撑满、内容超长不压缩，交给 `.main` 滚）。
**判据（新探针 `_vfit.py`）**：逐元素比 `scrollHeight > clientHeight`，找出真正被裁的盒子。

**坑 2：把面板硬撑高，反而"更松"。**
撑满之后控制台 panel 从 430 拉到 1010，但日志只有 7 行 → 面板内部留下 400px 空白，
**比不撑还松**。教训：**「松」是信息密度问题，不是高度问题。**
→ 撤掉 `.grid-2`/`.con-body` 的 `flex:1`，改 `align-items:start`，让面板高度由内容决定。

## 四、真正的解法：提密度（`_dense.py`，14 处，幂等）

| 位置 | 旧 → 新 |
|---|---|
| 侧栏 `.side-cap` padding | 14/8 → 10/6 |
| 侧栏世界行 `.world` padding | 8px → 6px（行高 50 → 42） |
| `.world-head` 上距 | 16 → 10 |
| `.tabbar` 上距 | 16 → 10 |
| `.content` 上距 | 16 → 12 |
| `.grid-2` gap / margin-top | 16 → 12 |
| `.panel` margin-bottom | 16 → 12 |
| `.metrics` gap | 12 → 10 |
| `.metric` padding | 13/14/14 → 10/12/11（卡片 200 → 155px） |
| `.metric .val b` 字号 | 30 → 26 |
| `.con-body` 字号 / 行高 | 15.5px/1.65 → **14.5px/1.5**（每行 25.6 → 21.8px） |
| `.con-body` min-height | 320 → 220 |

效果：概览页内容高 764 → 739；控制台面板正好被 7 行日志填满，无内部留白；
九屏 × 四档宽度仍全部 `SW==CW`（无横向溢出回归）。

## ⚠⚠ 本轮踩的坑

**坑 A：幂等检查的顺序**（`_hud_css.py`）。
脚本先插入含 `--hud-h` 字样的**注释**，再检查 `if '--hud-h' not in s` 决定要不要声明变量 ——
注释里已经含这个字符串，于是**变量声明被自己跳过**。
后果：`.hud { height: var(--hud-h) }` 解析失败 → 退化成 `auto` → **HUD 只有 27px 高**，
而且**不报错**，只有量 `hudH` 才发现。
→ 规矩：**幂等检查必须用「唯一锚点字符串」，别用「关键词是否出现过」**。

**坑 B：「被 HUD 压住」的判据量错了对象。**
一开始量 `main.lastElementChild.bottom > hudT`，于是 config/files/backup 三页全被误报 ——
`main` 是**滚动容器**，内容长的时候最后一个子元素本来就在视口外，
那是「需要滚动」，不是被压住。
→ 正解：量 **`main` 自己的可视底边**（`main.getBoundingClientRect().bottom`）。
修完九页全绿：`mainB == hudT == 756`，即主区底边**正好贴住** HUD 顶边，零缝隙。

# 后端补字段：名册的「游戏时长 / 最后在线 / 延迟」

用户拍板「把后端字段补上」（设计稿的行有「游戏 64 分」和「在线 · 27 ms」，后端原先没有）。

## 数据源：两处，别混

| 字段 | 来源 | 什么时候有 |
|---|---|---|
| `playTicks` / `lastSeen` | 世界目录下 `<world>/stats/<uuid>.json` + `<world>/playerdata/<uuid>.dat` 的 mtime | **离线也读得到** |
| `ping` | companion 插件上报（`CompanionPlayer.Ping`） | 只有**服在跑 + 装了插件**才有 |

⚠ **原版服务端不暴露玩家级 ping** —— 只有面板自带的 companion 插件给得出。
拿不到就不显示数字，**不编一个「0 ms」**。

## 实现

`internal/daemon/playerstats.go` 新增：
- `RosterExtra{PlayTicks, LastSeen, Ping}` —— 全字段 `omitempty`，
  让「没有」和「是 0」区分开。playTicks 为 0 = 没档案，不是「玩了 0 秒」。
- `rosterWant{Name, UUID}` —— 传 UUID 进去很重要：**正版服的在线玩家只有名字、
  面板算不出 UUID**，但 `whitelist.json` 里记着；不带上就一个人都读不出时长。
- `RosterExtras(id, want) map[string]RosterExtra` —— 批量版。
  + 键是**小写玩家名**（和前端合成总表的去重规则一致）。
  + 每人只读一个 stats 文件 + 一次 Stat，而不是逐个调 `PlayerProfile`。
  + **上限 `rosterExtraLimit = 300`**：白名单可能几百人，无上限会把一次 `/players` 拖成秒级。
  + 先给每个人**占位**（空 entry），否则 companion 的延迟没处可填。

`internal/daemon/players.go`：
- `PlayerRoster` 加 `Extra map[string]RosterExtra`（保证非 nil）。
- `PlayerLists` 里收集四份名单的人名（**带 UUID**）→ `RosterExtras` → 再用
  `CompanionSnapshot` 把在线玩家的 `Ping` 合并进去（名册里没有的人不凭空添行）。

- `TestRosterExtrasUsesUUIDFromRoster` —— 正版服（`online-mode=true`）下用名单里记着的

# 概览页最终定型（用户已确认的三件事）

| 诉求 | 落地 |
|---|---|
| **铺满全屏** | `.app { max-width: none; margin: 0 }`（删掉设计稿的居中留白） |
| **内容区左右间距** | `.main > .world-head/.tabbar/.content { padding: 0 16px }`（设计稿这里是 0） |
| **不要底部留白** | 概览页内容随高度伸缩，控制台吃掉剩余高度 |

## ⚠⚠ 又是「flex 收缩」把两列搞不等高

`flex: 1 1 auto` 让 `.grid-2` **可收缩** —— 矮屏下被压到 230px，而右列内容实际有 ~459px
（档案 + 16px 间距 + 快捷操作），**溢出容器**被裁（「快捷操作」只剩一条标题）。
用户看就是「控制台和右边高度不一样」。

→ 全改成 **`flex: 1 0 auto`（只长不缩）**：高屏撑满、矮屏保持自然高（放不下就整页滚，用户认可）。
→ 另给右列容器加 `overflow-y: auto`：万一还是比行高高，它自己滚，**不再溢出被裁**。

**规律（这已经是第三次了）**：这个项目里凡是「填满剩余高度」的地方，
一律用 `flex: 1 0 auto`，**不要用 `flex: 1 1 auto`** —— 收缩会去压内容，压坏的东西肉眼很难第一时间联想到 flex。

## ⚠ 探针又补了两条（都被我误判过）

- `vh` / `vw`：**无头下 `--window-size=W,H` 的实际视口比 H 小**（1440×900 实际只有 804 高）。
  之前拿 900 当基准去比 `mainB=804`，得出「内容差 96px」的错误结论。
- `DROP=`：**垂直**越界元素（`.main` 内的元素底边超过 main 可视底边）。
  `CUT=` 那条只查**水平**方向，垂直方向必须单独查 —— 否则「被底部健康条压住」永远抓不到。

## 其他页面的状况

用户：**「除了玩家页面不用动，其他页面现在都是这个情况，排版排版不对，左右间隙没有」**
→ 意思是玩家页版式可以（之前那轮改过），**其余七页要照「先复制、再接接口」搬设计稿**。
左右间距那条已经在 `.main > .content` 上，对所有页生效（实测玩家页 `contentPad=12px/16px/16px`）。

## 「新建世界」页不走 PageFrame —— 底部按钮被 HUD 压住

`view === 'create'` 是一条**独立分支**，直接渲染 `<CreateWizard/>`，**没有 `.main` 外壳**
（`?view=create&probe=1` 连 `<main>` 元素都查不到）。于是它拿不到 `.main` 的
`padding-bottom: 50px`（给底部健康条让位）—— 最后那排「取消 / 上一步 / 下一步」**被 HUD 盖住**。

→ 在 CreateWizard 自己的滚动容器上加 `pb-[calc(var(--hud-h)+10px)]`。

⚠ 教训：**凡是绕过 PageFrame 的视图（create / market / pack），都要自己给 HUD 让位。**
（market / pack 自带 PageFrame，所以只有 create 中招。）

⚠ 小坑：在 `return (` 之后、根元素之前写 `{/* 注释 */}` 会报
「JSX expressions must have one parent element」—— `(` 后面只能有一个表达式。
要写注释就用普通 JS 注释 `/* ... */`。

# 文字层级：设计稿的字阶（拿数字对照，不靠感觉）

`design.css` 里的字号分布（`grep -oE "font-size: *[0-9.]+px" | sort | uniq -c`）：

| 字号 | 次数 | 用途 |
|---|---|---|
| **12.5px** | 14（最多） | 正文 / 次级说明 |
| 13px | 12 | `.field .lb` 字段标签 |
| 14px | 9 | 控制台、正文强调 |
| 12px | 9 | `.field .hint` 提示 |
| 11px | 9 | 眉标 eyebrow |
| 10.5px | 8 | chip / badge |
| 15px | 6 | `.sec-head h2` 区块标题、`.inp` 输入值 |
| 13.5px | 4 | 行标题 |
| 20px | 1 | `.world-title h1` 页面主标题 |

**向导里我改掉的**（原来偏离了）：
- h1 `text-[22px]` → **`text-[20px]`**（设计稿没有 22px 这一档）
- 区块标题原来挂着 `border-b-[3px] border-black`（旧卡片的黑粗线）+ 16px
  → 改成 **15px、去掉黑线**（设计稿的 `.sec-head h2` 就是 15px，区块靠留白分，不靠分隔线）
- 卡片栅格 gap `14px` → **12px**（设计稿 `.grid-2` 的 gap）
- 类型名 14px → 13.5px

## 卡片排版：chips 必须吸底

原来描述用 `min-h-9` 固定高，chips 跟在后面 —— 每张卡描述长短不一，
chips 的垂直位置就参差不齐，**一整排看过去是锯齿**。

→ 改成：`.type-card` 加 `flex flex-col`，描述 `flex-1`（吃掉剩余高度），
chips 容器靠 `mt-2` 落在底部。同一行的卡片 **grid 默认 stretch 已经等高**，
配上吸底之后，一整排的 chips 就对齐了。

**通用规律**：**网格里卡片内的元素要「吸顶 / 吸底」对齐时，卡片必须自己是 flex 纵向容器。**
光靠 grid 的 `stretch` 只能让卡片外框等高，管不了里面。
