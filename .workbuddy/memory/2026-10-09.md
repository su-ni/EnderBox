- 根因**不是**「没写动画」，而是**写了但无声**：`design-overrides.css:465` 早就给
  `.dlg-overlay > .dlg` 挂了 `animation: rise ...`，可 `@keyframes rise` **只定义了 `to` 帧**
  （`opacity:1; transform:none`），必须靠元素自带初始 `opacity:0/translateY` 才有效果，
  而 `.dlg` 没有初始状态 → 从终态演到终态，看不出任何变化。
- 另一层坑：我在文件末尾补的 `.dlg { animation: dlgIn }` **被压过** ——
  `.dlg-overlay > .dlg` 是**两个类**的特异性（不是层序问题），单类 `.dlg` 赢不了。
- 修法：把 :465 那条改成 `animation: dlgIn var(--dur) var(--ease) backwards`（`dlgIn` 有 `from` 帧），
  并删掉末尾那条会误导人的冗余规则 + 注释说明为什么。
- ✅ 验证：`animationName=dlgIn`、`fill=backwards`、**`transform` 动画后回 `none`**（无 both 的包含块坑）。
- **教训：`.reveal`/`.anim-in` 那类「只有 to 帧」的关键帧，必须配元素的初始值；否则是死动画。**

  `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`）。
- **守护进程启动 java 那一层没做** → java **沿用守护进程的控制台**。
  Windows 上关掉控制台 → 控制台里的进程收到关闭事件 → **java 跟着死**。
- **完全没有接管逻辑**（grep 不到 `reconcile` / `adopt` / 孤儿进程扫描）。

## 由此产生的两个坑

1. **关面板 = 关服**（且是**硬杀**，不是 `stop`）—— 存档来不及写盘，有损坏风险。
2. 更糟：**重开面板后实例显示「已停止」，但 java 还在后台跑**。
   这时用户点「启动」→ **开出第二个服务器** → 端口冲突 / 世界文件被两个进程同时写。

## 该怎么做（待用户拍板）

- **① 让 java 也脱离**（补 `SysProcAttr`，或启动时写 pid 文件 + detached）。
- **② 启动时扫一遍「孤儿进程」并接管**：按 pid 文件 / 命令行特征找回已在跑的实例，
  把状态标成 running 并把日志接回来（或至少**如实显示「有个我没在管的服务器在跑」**）。
  这条比①更重要 —— ①只解决"别死"，②解决"死了之后的一地鸡毛"。

## ⚠⚠ 但「加个 flag 让它脱离」这条试过了，**走不通**（已回退）

按 `cmd/desktop` 的现成做法给 java 加 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`：

| 组合 | 结果 |
|---|---|
| 不加 | **PASS，2.2 秒** |
| 加了 | **FAIL，60 秒超时**（挂的是核心护栏 `TestE2EConsoleStopIsNotCrash`） |

**已排除两个想当然的解释**：
1. 不是「java 起不来」—— 单独的 flag 对照实验（`F:/tmp/flagprobe`，`java -version`）
   四个组合全部 67ms 正常返回；
2. 不是「没 flush」—— `tools/fakeserver/FakeServer.java:108` 明确调了 `System.out.flush()`。

**现象**：detached 之后**这个常驻进程的 stdout 管道拿不到数据**（根因未定位）。

**但真正致命的是下面这条**（就算根因查清也没用）：

> **管道断了就接不回来。** 面板靠 stdin/stdout 管道跟 java 说话；面板一退管道就断。
> 重开面板时 java 还在跑，但它的 stdout 指向**一条已经没有读者的管道** ——
> **没有任何办法重新接上。**
>
> 所以「**脱离 + 接管**」用管道方案**自相矛盾**，这是架构死结，不是实现细节。

**正解（写进 `docs/PROCESS-LIFECYCLE.md`）**：
- **方案 B（完整答案）**：绕开管道 —— 读 `logs/latest.log` + 命令走 **RCON**。
  代价：要帮用户在实例里 `enable-rcon`（**安全相关，必须告知**）、日志有写盘延迟、
  还要做 pid 文件 / 孤儿扫描 / RCON 客户端 / 「谁在管这个实例」的状态机。
- **方案 C（先做，低成本）**：不做脱离，改成**捕获面板自身的关闭事件 → 先给所有运行中的实例
  发 `stop` → 等写盘 → 再退**。消除最要命的「硬杀导致坏档」，但不满足「服继续跑」。
- **别再试「加 flag 脱离」**：已证伪。

## ✅ 改做方案 C：优雅停服（已落地）

用户拍板：**不接受**「只能看+杀、不能发命令」的残缺接管，**不开 RCON** → 改做方案 C。

**实现**（`internal/daemon/shutdown.go` + `cmd/server/main.go` + `cmd/server/console_{windows,other}.go`）：

- `Manager.StopAllGracefully(timeout)` —— **并发**给所有运行中的实例发 stop。
  ⚠ 必须并发：串行的话 3 个实例就是 3×timeout，而窗口关闭给的总时间只有约 5 秒。
- `Manager.RunningIDs()` —— 抽出来是为了让「退出时有没有东西要停」可以被测试直接问。
- `main` 里三条退出路径都接上：**Ctrl+C**（`os.Interrupt`）、**SIGTERM**、
  **关控制台窗口**（`CTRL_CLOSE_EVENT`，Windows 专有）。
- ⚠ **等待上限取 4 秒**（小于 Windows 给的约 5 秒），且空闲时**立刻返回**——
  写成「无脑等到 timeout」会把关窗口的余量吃光，等于白做。
- ⚠ **`log.Fatalf` 换成 `log.Printf`**：优雅退出时 `ListenAndServe` 会返回
  `ErrServerClosed`，那是**正常路径**，用 Fatalf 会把它当错误报出来。

⚠⚠ **关控制台窗口必须单独挂处理器**：Windows 上 Ctrl+C 会被 Go 运行时转成 `os.Interrupt`，
但 **CTRL_CLOSE_EVENT / CTRL_SHUTDOWN_EVENT 不会** —— signal channel 里什么都收不到。
不补这一条，就会出现最气人的情况：**按 Ctrl+C 能优雅停服，点右上角那个 ✗ 却把服硬杀了**。
用 `SetConsoleCtrlHandler` 且 **`Add=1`（追加）**，别把 Go 自己的处理器顶掉。

**测试**（`internal/daemon/stopall_test.go`，3 条全过）：
空闲立即返回（防「干等到超时」）、停止态不算 running、空 store 不 panic。
⚠ `shutdown_test.go` **已存在**（停服判定的），差点覆盖 —— 新文件叫 `stopall_test.go`。

**未验证**：Windows 上真的按 Ctrl+C / 点 ✗ 的实机行为。无头环境没法可靠地自动发
`CTRL_CLOSE_EVENT`（`taskkill` 不带 `/F` 只对 GUI 程序发 WM_CLOSE），**需要手动点一下**。

# 星图四轮：做成**真·星系**（会转 / 能转 / 点了不跳）—— 用户「不是这样，不是这样」

## 用户原话还原（三条硬需求）
> 「首先它是会转的好吗？它是会有动态效果的」「他点击后可以跳转…就算不跳转了，做得好一点，
> 放到他这里之后除了显示这些信息之外，点击可能用户不想跳转，他只是想了解一个大概」
> 「不只是平移的，可以给他转来转去那种」

## ⚠⚠ 先扒站方真相：MC 百科那个图**其实不会转**
`/static/public/js/class/mc.class.functions.js`（21KB，直连可下）里的关键参数：
```
force:{repulsion:900, edgeLength:200, gravity:.1, friction:.2, layoutAnimation:!0}
animationDuration:2e3, animationEasingUpdate:"quinticInOut"
roam:!0, draggable:!0, scaleLimit:{min:.5,max:1.5}
```
- **`layoutAnimation:true`** = 力模型一直在跑 → 点持续轻微游动、慢慢稳定。用户看到的「会转」是这层动态感。
- 点击行为：`if(t.dataType==="node"){var e=a.nodes[t.dataIndex].classID; e&&window.open("//www.mcmod.cn/class/"+e+".html")}`
  → **站方就是直接跳转**，没有"了解大概"的卡片。
- 站方也有层级过滤：函数 `l(a,t,e)` 里 `a.deep<=t && n<=e` —— 跟我们做的档位同源。
- 滚轮缩放时动态调标签字号：`fontSize=(12*zoom).toFixed()`。
- 有个 `#class-relation-chart-tobase` 按钮 = 复位中心。

**结论**：站方给的是「动态感」，用户要的「转来转去」是我们的**增量**。两层都做。

## 实现（三件套）

### ① 会转 —— 入场 + 自转 + 呼吸
- **持续自转**：rAF 每帧 `yaw += dt*0.00006`（约 0.06°/帧 ≈ 3.4°/分钟，很缓）。
- **呼吸抖动**：每点按 id 哈希出相位/速度，`sin(t*spd+ph)*0.004`（归一化空间 → 屏幕约 1.5~2px）。
  ⚠ 幅度必须小（>2px 会读成"图在抖/渲染不稳"），且**确定性**（无随机 → 可截图回归）。
- 尊重 `prefers-reduced-motion`；手动拖拽后 2.5s 内暂停自转（否则自动转抵消用户操作）。
- 工具栏加**自动旋转开关**（`.ibtn.on`）。

### ② 转来转去 —— 伪 3D 旋转（拖拽 = 转动，不是平移）
- 状态 `rot{yaw,pitch}`；左键横拖改 yaw（0.006 rad/px）、竖拖改 pitch（限 ±1.15rad 防翻转）。
- **z 坐标构造**：2D 力布局没有第三轴。按「归一化半径 → 球面 `z=±sqrt(1-r²)`」造壳，
  正负号用 **节点 id 哈希**决定（确定性）→ 点云是有厚度的球，不是平盘。
- 投影顺序：绕 Y(yaw) → 绕 X(pitch) → 透视 `s=1/(1+z2/D)`，`D=4.5`。
- **绘制顺序按 z2 排序**（远的先画、近的后画）→ 转动时前半球压住后半球，有真遮挡。
- 透视系数 `s` 同时作用于圆半径和标签字号（近大远小）；箭头端点也乘 `s`（否则转动时箭头穿圆）。
- ⚠ `ordered` 的 useMemo 依赖里**必须含 rot.yaw/pitch/t**，否则转动时遮挡关系冻住。

### ③ 点了不跳 —— 就地信息卡
- 点节点 → 卡在**画布下方的正常文档流**里（跟图例同层，不浮层 —— 浮层会盖住图，用户想边看边读）。
- 卡内容：分类色竖条 + 名字 + 分类 chip + 关系句 + 「依赖 N / 被 N 依赖」+ 简介(3行截断) + 「去 MC 百科看完整条目」链接。右上角 × 关闭。
- 关系句 `relationSentence()`：直连的按站方口径（「X 是 钠 的拓展模组」），
  ⚠⚠ **间接相连的必须也给一句**（实测 302 点里 277 个不与中心直连，只写直连会得到空句 ——
  第一版就踩到：Chisel Reborn 的卡里那句是空的）→ 用 `deep` 说「距 钠 (Sodium) 4 层，经前置/依赖关系与之相连」。
- 被点中的节点 `.is-picked` 青描边 3px + 名字强制显示，跟卡片呼应。

## ⚠⚠ 探针假象（这轮踩了三个，全是自己骗自己）
1. **按 DOM 顺序取样测运动**：绘制顺序每帧按深度重排 → 前后两帧同一位置是**不同的点**，
   量出的"位移"是错位不是运动（第一版 SPIN_OFF 误报 max=394）。**正解**：给 `<g>` 加 `data-nid`，按 id 取样。
2. **没滚进视口就点**：挑到的节点 y=2862（视口才 1000）→ `elementFromPoint` 落空、点击打不到东西，
   误报「点击无效」。**正解**：`scrollIntoView({block:'center'})` 先滚。
3. **SVG 子元素溢出误报**：`.mcg-svg{overflow:hidden}` 会裁掉画到框外的点，但
   `getBoundingClientRect` 仍返回**未裁切**坐标 → mobile 探针误报 5 个 522px 溢出。
   **正解**：判溢出时先检查自身/祖先有没有 `overflow:hidden|clip`，有就跳过（已改进 `probe_mobile.mjs`）。
4. 附带：**自动自转会让 hover 探针落空**（取坐标→发事件之间节点飘走）→ 探针先点「停止自转」。

## 验收（dev-mcg16，全绿）

- **SPIN_OFF** avg 2px、max 4（开关能停，只剩呼吸）✓

## ⚠⚠ 星图性能修复（22:00-22:40，用户实测报了「鼠标移入移出闪屏」+「滚轮放大卡卡的」）

### 根因：**三个独立的问题**，别当成一个
1. **每帧重建 DOM**。`t`（呼吸时钟）放 React state → 每帧 `setT` → `ordered` 依赖 `t` →
   每帧重建 302 点排序数组 + React 重渲染整棵 SVG 树。鼠标悬停又叠加一次 state 变化。
   → 症状就是闪屏。**修法：动画态全挪出 React**（yaw/pitch/t 存 ref，rAF 直接改 DOM）。
2. **每帧 appendChild 重排**（第一版修法自己引入的）。为做深度遮挡，每帧对 302 个 `<g>` 调
   `appendChild` → 实测 **DOM mutation 49830 次/1.5s**，帧率 31fps。appendChild 一个已在树里的
   节点 = 摘除+插入两次树变更。**修法：深度档容器（`BUCKETS=12`），只在跨档时搬家**（缓慢自转时 ≈0）。
3. **每帧 1356 次边属性写入**。339 条 `<line>` × 4 属性（x1/y1/x2/y2）= 最大开销。
   **修法：边按源节点颜色分组，每组一条 `<path>`，每帧每组只写一次 `d`** → 从 1356 降到 3~5 次。
   ⚠ 代价：path 挂不了 marker 箭头（有意取舍，自转时箭头本就糊）。
   外加**逐属性变更检测**（transform/r/opacity/fontSize 值没变就不写）。

### 结果（可信判据：rAF 帧间隔 p50）
| 阶段 | p50 | 备注 |
|---|---|---|
| 原版（每帧 React 重渲染） | — | DOM mut 49830/1.5s |
| 档位容器版 | 33.3ms（30fps） | DOM mut **0**，但边还是 1356 次写 |
| **最终版（边批 path + 变更检测）** | **16.7ms（60fps）** | avg 27.9→18.9，max 66.7→50 |

### ⚠⚠ 所有权冲突（这轮最坑的一个 bug）
节点原本由 **React 渲染**、effect 再每帧把它们搬到深度档容器里
→ **两个所有者改同一棵子树** → React reconciler 按旧结构 insertBefore，与手写 DOM 打架
→ **节点持续丢失 302→282→247→202**（渐进式，不报错）。
**正解：容器的子节点全部由 effect 用 `createElementNS` 创建并全权维护**，
React 只渲染 `.mcg-nodes` / `.mcg-edges` **空容器**。所有权单一 → 302 稳定。
（t 型偷懒做法：节点 JSX 里渲染、effect 里搬 —— 别再这么干。）

### 滚轮语义改向（用户明确要求）
- 原「画布内滚轮放行给页面滚动」（项目规范#6）→ **改为画布内滚轮 = 缩放**。
  理由：星图是画布不是文档流，地图/PDF/echarts `roam:true` 都这样。
- 触屏仍走 `touch-action: pan-y`，纵向滚动穿透（那条 CSS 没动）。

### 探针假象（这轮又踩两个，共 6 个了，务必先怀疑探针）
5. **headless 无法合成「非 document 滚动容器」的原生滚动手势**。
   `synthesizeScrollGesture`/`dispatchTouchEvent` 在画布内、画布外、甚至无星图区域
   滚动量**都是 0** → 拿「scrollTop 变化」当判据必然假阴性（白折腾两轮）。
   **正解判据 = 看有没有 JS 取消触摸滚动**：`computed touch-action === 'pan-y'`
   + 合成 touchstart/touchmove 后 `e.defaultPrevented` 全为 false。已重写 `probe_touch.mjs`。
6. **SVG `<g>` 的 `getBoundingClientRect` 中心点 ≠ 圆心**。
   节点用 `<g style="transform:translate(x,y)">` 定位后，`<g>` 的 bbox **含右侧 label 文本**，
   中心偏到「圆+名字」中间 → hover 必然落空（`probe_hover.mjs` 误报 NO_TIP）。
   **正解**：取 `circle.mcg-circle` 的 rect 算圆心。
   ⚠ 另：`probe_allnames.mjs` 的「滚轮滚页面」断言已过时 → 改成「页面不动 + 星图缩放」。

### 判据可信度（重要工作方法）
- **headless 的 `Performance.getMetrics` 的 Duration 字段是秒级粒度**（LayoutDuration 经常正好 1000），
  拿它当毫秒用会得出荒谬结论。**要测 JS/渲染开销，用 rAF 帧间隔 p50**（这个是真的）。
- headless `--disable-gpu` ⇒ `transform` 走软件光栅，**帧率数字比真机低**；
  但同一环境下的**相对对比**可信。别拿 headless 的绝对 fps 下结论。
